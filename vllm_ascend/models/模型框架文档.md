# 第 1 部分：推理框架背景知识

## 1.0 全文形状符号约定（必读）

本仓库所有模型处理的是**展平的 token 流**：一个 batch 里所有请求的所有 token 拼成一条序列，模型代码不区分请求边界（边界信息在元数据里）。全文使用以下符号：

| 符号 | 含义 | 示例值 |
|---|---|---|
| `N` | num_tokens，batch 内展平 token 总数 | decode 时=批内请求数；prefill 时=prompt 总长 |
| `B` | num_reqs，请求数 | 32 |
| `H` | hidden_size，隐藏维 | 4096 |
| `L` | 序列长度（单请求） | 4096 |
| `E` | vocab_size，词表大小 | 152064 |
| `h_q` / `h_kv` | Q 头数 / KV 头数（TP 切分后每卡） | 64 / 8 |
| `d_h` | head_dim，每头维度 | 128 |
| `d_lora` | kv_lora_rank，MLA 压缩维 | 512 |
| `q_lora` | q_lora_rank，Q 侧压缩维 | 1536 |
| `d_nope` / `d_rope` | MLA 中 K 的无位置段 / 旋转段维度 | 128 / 64 |
| `G` | MoE 专家总数；KDA 分组卷积的组数 | 256 / 32 |
| `K` | MoE top-k；候选格的候选数 | 8 |
| `tp` | tensor_parallel_size | 8 |
| `S` | KDA 递归状态矩阵 `[d_k × d_v]`（每头） | 128×128 |

**形状书写的统一格式**：

```
张量名 [形状]  ←── 算子/操作 ──→  张量名 [新形状]
```

## 1.1 大模型推理的计算过程

三个基本概念：

1. **Token（词元）**：模型处理文本的最小单位。文本先被分词器切成 token 序列，每个 token 对应词表里的一个整数 id。
2. **Embedding（词嵌入）**：一张 `[E, H]` 的查找表。输入 token id `i`，取出第 `i` 行，得到语义向量。

```
input_ids [N]              例: [1523, 871, 45, ...]
   │ embed_tokens（VocabParallelEmbedding，按词表行切 TP）
   ▼
hidden_states [N, H]       例: [512, 4096]
```

3. **自回归生成**：每次前向只产出**下一个 token** 的概率分布：

```
hidden_states [N, H] ── lm_head [H, E] ──→ logits [N, E]
   │ 采样（只取最后 1 个位置，例: logits[-1] [E]）
   ▼
下一个 token id（标量）→ 拼回输入 → 再来一次前向
```

生成 100 个 token = 100 次完整前向。推理优化的主题：让每次前向更便宜，或一次前向多产出 token（投机解码，1.9）。

## 1.2 Prefill 与 Decode 两阶段

| | Prefill | Decode |
|---|---|---|
| 做什么 | 一次吃进整个 prompt | 每次只算 1 个新 token（每请求） |
| batch 形状 | `N` = prompt 总长（可能上万） | `N` = B（每请求 1 token） |
| 核心算子 | GEMM `[N,H]×[H,H']`（矩阵×矩阵） | GEMV `[1,H]×[H,H']`（矩阵×向量） |
| 瓶颈 | 算力 | 访存带宽 |
| 优化方向 | 分块并行、充分填充算力 | KV Cache、批处理（把 B 个 GEMV 拼成 GEMM）、量化 |

**GEMM vs GEMV 的本质**：GEMM 每搬 1 字节权重能做 n 次乘加（权重被复用）；GEMV 每字节只做 1 次乘加（权重只用一次）——这就是 decode 阶段"批处理"的根本动机：B=32 时，`[32, H] × [H, H']` 权重复用 32 次。

## 1.3 Transformer 解码层解剖（含 shape 流）

现代大模型 = 词嵌入 + n_layers 个相同的解码层 + 输出头。解码层结构（**全文最重要的图**）：

```
hidden_states [N, H] ──────────────────────────┐ residual [N, H]（存一份）
   │                                           │
   ▼                                           │
RMSNorm: [N, H] → [N, H]                       │
   ▼                                           │
Self-Attention: [N, H] → [N, H]                │
   ▼                                           │
   + ◄─────────────────────────────────────────┘  相加: [N,H]+[N,H] → [N,H]
   │                    ──┐
   ▼                      │ residual [N, H]
RMSNorm [N, H]             │
   ▼                      │
MLP / MoE: [N, H] → [N, H] │
   ▼                      │
   + ◄─────────────────────┘
   ▼
输出 hidden_states [N, H]（交给下一层）
```

### 1.3.1 RMSNorm

```
x [N, H] → y = x / sqrt(mean(x², dim=-1) + ε) * γ → [N, H]
```

逐 token 归一化，输出乘可学习缩放 γ `[H]`。`GemmaRMSNorm` 变体输出乘 `(1 + γ)`（γ 零初始化 = 恒等变换）。

**融合调用惯用法**（本仓库所有解码层都有）：

```
(x, residual) 双输入 → 一次算子完成 x = x + residual; y = norm(x)
→ 返回 (y [N,H], 新residual [N,H])     省一次显存读写
```

> **语法点** `mean(x², dim=-1, keepdim=True)`：`dim=-1` 表示最后一维；`keepdim=True` 让结果保持 `[N, 1]` 而非 `[N]`——只有 `[N, 1]` 才能与 `x [N, H]` 广播相除（广播规则：从尾维对齐，尺寸为 1 的维自动扩展）。
>
> **语法点** `y, residual = norm(x, residual)`：元组解包——函数返回二元组，一行接收两个变量。这是本仓库前向代码的标准写法（RMSNorm 的双参融合调用到处都在用）。

### 1.3.2 Self-Attention 的完整 shape 流（以 GQA 为例）

```
hidden_states [N, H]
   │ qkv_proj（QKVParallelLinear，一个 GEMM 出三段）
   ▼
qkv [N, h_q·d_h + 2·h_kv·d_h]              例: [N, (64+8+8)×128 = 10240]
   │ split
   ├─→ q [N, h_q, d_h]                     例: [N, 64, 128]
   ├─→ k [N, h_kv, d_h]                    例: [N, 8, 128]
   └─→ v [N, h_kv, d_h]

Q/K 归一化（reshape 到头维独立 norm）:
   q [N, 64, 128] → view [N·64, 128] → norm → reshape 回 [N, 64, 128]

RoPE（按 positions [N] 旋转 q/k，形状不变）:
   q,k [N, heads, d_h] → [N, heads, d_h]

注意力计算:
   scores [N, h_q, L] = q @ kᵀ / √d_h      （k 含历史 cache 时 L 是 KV 长度）
   probs  [N, h_q, L] = softmax(scores)
   out    [N, h_q, d_h] = probs @ v

输出投影:
   out [N, h_q, d_h] → flatten [N, h_q·d_h] → o_proj → [N, H]
```

`num_heads`（多头）：把 hidden 切成多份独立做上述计算，不同头关注不同信息。RoPE 给 Q/K 加随位置旋转的角度，使内积包含相对距离信息；`partial_rotary_factor` 表示只旋转前一部分维度。

> **语法点** `q.view(N, 64, 128)` vs `q.reshape(N, 64, 128)`：view 只改形状不改数据（零拷贝），但要求内存连续——切片/转置后的张量用 view 会报错；reshape 允许不连续（必要时隐式拷贝一次）。本仓库遵循"能 view 就 view"（各模型 `_qk_norm` 里的 `reshape → norm → reshape` 链就是先整形到 `[N·heads, d_h]` 再归一化）。
>
> **语法点** `q @ k.transpose(-1, -2)`：`@` 是 `torch.matmul` 的运算符重载；`transpose(-1, -2)` 交换最后两维（前面的 batch 维不动）。

### 1.3.3 残差流

图中的两条 residual 旁路构成从第一层直通最后一层的"高速公路"。本仓库三个模型把单车道升级为多车道（Hyper-Connections / mHC / MHC / 注意力残差块，见第 3 部分），多路形态下残差是 `[N, hc_mult, H]`。

## 1.4 KV Cache 与 PagedAttention

### 1.4.1 为什么需要 KV Cache

生成第 100 个 token 时注意力要"看"前 99 个 token，而它们的 K/V 不会变——缓存下来避免重算。

**Cache 形状与显存账**（GQA 例）：

```
每层 cache: k_cache [num_blocks, block_size, h_kv, d_h]
           v_cache [num_blocks, block_size, h_kv, d_h]
每 token 每层字节数 = 2(K和V) × h_kv × d_h × dtype字节
                    例: 2 × 8 × 128 × 2(BF16) = 4 KB

总显存 = 4 KB × 64 层 × 100,000 token ≈ 25 GB   ← 比权重本身还大
```

这就是为什么五大模型族里四个的核心创新都是压缩 KV Cache（1.5）。

### 1.4.2 PagedAttention：块、块表、槽位映射

Cache 按固定大小 **block**（如 128 token）分页。三个核心数据结构：

```
block_table [B, max_blocks]        例: [[17, 3, 42], ...]
    请求 0 的 token 分布在物理块 17/3/42 中（第 0~127 个在块 17…）

slot_mapping [N]                   例: [块42的槽100, 块42的槽101, ...]
    本 batch 每个 token 写进 cache 的物理位置

reshape_and_cache(k, v, k_cache, v_cache, slot_mapping)
    k [N, h_kv, d_h], v [N, h_kv, d_h] → 按 slot_mapping 散射进 cache
```

### 1.4.3 vLLM v1 的"申报-规划"机制

模型每层实现 `get_kv_cache_spec()` 申报布局（块大小/KV 头数/头维/dtype），调度器统一规划显存；返回 `None` 表示该层不要 cache（线性注意力层）。

## 1.5 注意力变体族谱：MHA → GQA → MLA → 稀疏/线性

每 token 每层 cache 对比（d_h=128，BF16）：

| 变体 | cache 内容 | 每 token 每层 | 思路 |
|---|---|---|---|
| MHA | 64 头的 K 和 V | 32 KB | 原始设计 |
| GQA | 8 个 KV 头 | 4 KB | 每 8 个 Q 头共享 1 份 KV |
| **MLA** | 1 个压缩向量 | (512+64)×2 ≈ 1.1 KB | 不存 K/V，存压缩摘要 |
| 稀疏注意力 | 同上 | 同上 | cache 不减，**计算量**大减 |
| 线性注意力 | 固定状态 | 0（状态大小恒定） | 用状态递归替代 cache |

### MLA 的完整 shape 流（必须掌握，4/5 个模型族在用）

```
【写 cache 侧】
hidden_states [N, H]
   │ fused_qkv_a_proj（一个 GEMM）
   ▼
[q_a | kv_a]  [N, q_lora + d_lora(+d_rope)]      例: [N, 1536+512+64]
   │ split
   ├─ q_a [N, q_lora] → q_a_layernorm → q_b_proj → q [N, h_q·(d_nope+d_rope)]
   │                                                    例: [N, 64×192]
   ├─ kv_a [N, d_lora] ──→ 存进 cache！          例: [N, 512]  ← 只存这个
   └─ k_rope [N, d_rope] ─→ 存进 cache！         例: [N, 64]   ← 只存这个

【cache】每 token 每层: c_kv [d_lora] + k_rope [d_rope] = [576]

【读 cache 侧（decode 注意力时在线升维）】
c_kv [d_lora] → ×Wk_up [d_lora, h_kv·d_nope] → k_nope [h_kv, d_nope]
c_kv [d_lora] → ×Wv_up [d_lora, h_kv·d_h]    → v [h_kv, d_h]
K = concat(k_nope, k_rope) [h_kv, d_nope+d_rope]
→ 与 q 做 attention → out [N, h_q·d_h] → o_proj → [N, H]
```

**RoPE 解耦的原因**：RoPE 是旋转操作，先旋转再压缩就恢复不出来，所以位置相关的 `k_rope` 段单独存、不参与压缩。这就是 `qk_nope_head_dim / qk_rope_head_dim / kv_lora_rank` 三个配置的含义。

### 稀疏注意力（闪电索引器）

```
【索引器：便宜的小注意力选上下文】
q_index [N, 1, 128]（低维，可 INT8）
k_index [L, 1, 128]（低维，可 INT8，独立 cache）
score [N, L] = q_index @ k_indexᵀ → topk → indices [N, 1, topk]

【主注意力：只对选中的 token 精确计算】
q [N, ...] 只与 indices 指向的 KV 做精确 MLA 注意力
复杂度从 O(N·L) 降到 O(N·topk)
```

"top-k 的粒度"是各家分化点：DeepSeek V4 按 token 选、MiniMax M3 按 block 选、GLM-5.Next 按 4-token 池选。

### 线性注意力（KDA / Gated DeltaNet）

```
状态 S [d_k, d_v]（每头一个，例: [128, 128]，大小恒定）

每 token:
   S ← a_t · S + β_t · k_t v_tᵀ        k_t [d_k], v_t [d_v]
        │ a_t∈(0,1) 遗忘门，β_t 输入门
   o_t [d_v] = q_tᵀ S / (q_tᵀ u_t + ε)   q_t [d_k]

无 cache、每 token O(1)。代价：表达能力弱于 softmax 注意力 → 与全/稀疏注意力层混合使用
```

## 1.6 MoE：混合专家模型

```
hidden_states [N, H]
   │ gate（小投影，FP32）
   ▼
router_logits [N, G]                  例: [N, 256]
   │ top-k + softmax（可选 renormalize / 分组路由）
   ▼
topk_weights [N, K], topk_ids [N, K]  例: [N, 8]
   │ 融合 MoE 内核: 按 topk_ids 把 token 分发给专家
   │   每个专家: [n_dispatched, H] → MLP → [n_dispatched, H]
   │   再按 topk_weights 加权求和
   ▼
out [N, H] = Σ_k topk_weights[:,k] · expert_k(x) + shared_experts(x)
```

本仓库涉及的 MoE 概念：

| 概念 | 含义 |
|---|---|
| `e_score_correction_bias [G]` | 无辅助损失路由：给冷门专家得分加偏置，缓解负载不均 |
| `shared_experts` | 恒激活的公共专家，实现为中间层加宽的单 MLP（等价多个并联） |
| `routed_scaling_factor` | 路由输出缩放 |
| EPLB | 逻辑专家↔物理专家映射 + 冗余副本热更新 |
| 潜空间 MoE（Kimi） | 专家在降维空间工作（见 3.4.2） |
| `FusedMoEFactory` | vLLM 融合 MoE 内核工厂：路由+专家 GEMM+加权求和一次完成 |

## 1.7 并行策略

```
              切什么            通信什么             本仓库体现
TP 张量并行   权重的行/列        每层 2 次 all_reduce  QKVParallelLinear/RowParallelLinear
PP 流水线     层区间            分界传 1 个张量       IntermediateTensors/PPMissingLayer/make_layers
DP 数据并行   请求              （推理几乎无通信）     视觉塔数据并行
EP 专家并行   专家到不同卡       token 路由到专家卡    get_ep_group/物理专家区间
SP 序列并行   token 到不同卡     注意力前 gather       common/ops/sequence_parallel.py
```

### TP 的 shape 流（以 QKV 投影为例）

```
总 QKV 权重 [H, (h_q_total+2·h_kv_total)·d_h] 按输出维切成 tp 份
每卡: qkv_proj_shard [H, ((h_q_total+2·h_kv_total)/tp)·d_h]

forward:
x [N, H] → 每卡 GEMM → qkv_local [N, (h_q+2·h_kv)·d_h]     （列切分，无需通信）
注意力 → out_local [N, h_q·d_h]（各卡只有自己头的结果）
o_proj（行切分）→ partial [N, H] → all_reduce 求和 → [N, H]  ← 每层 1 次通信

KV 头数 < tp 时复制（MLA 单 KV 头 8 卡 → 每卡同一份副本，num_kv_head_replicas）
```

### PP 的 shape 流

```
卡0（层 0-15）: ... → hidden [N, H], residual [N, H]
   → IntermediateTensors({"hidden_states": [N,H], "residual": [N,H]})   只传 1 组张量
卡1（层 16-31）: 从 intermediate_tensors 恢复 → 继续 → ... → lm_head → logits [N, E]
非本阶段的模块 = PPMissingLayer()（占位不占显存）
```

### SP 的 shape 流（详见 2.5.1）

```
x [N, H]，tp=8，N=1003
   │ 补零对齐（(-N) % tp = 5 → pad 到 1008）
   ▼
x [1008, H] → sp_shard → 每卡 [126, H]
   │ 非注意力层直接在本地分片算（激活显存 ÷ tp）
   ▼ 进注意力前
sp_all_gather → 每卡拿到全量 [1008, H]
   │ 注意力（需要看全部 token）
   ▼ 出来后
sp_reduce_scatter → 一次通信完成"部分和规约+重切分" → 每卡 [126, H]（已是完整和）
```

## 1.8 量化

| 格式 | 字节 | 要点 |
|---|---|---|
| BF16 | 2 | 默认精度 |
| FP8 E4M3 | 1 | **最大值 448**，超过溢出 → 代码里的 `clamp(±448)` |
| FP8 E5M2 | 1 | 范围大精度低 |
| INT8 | 1 | 对称整数量化 |
| MXFP8/MXFP4 | 1/0.5 | 每 32 个值共享一个 FP8 scale（OCP MX 标准） |

三种量化对象：权重（W8A8，激活动态量化 `npu_dynamic_quant`）、KV Cache（FP8，固定 scale 时 clamp+cast 即可）、索引器 q/k（INT8，配 Hadamard 旋转均摊能量降低量化误差）。

## 1.9 投机解码

```
propose（草稿，便宜）: 连续猜 k 个候选 token
verify（目标，一次前向）: 并行验证 k 个位置 → 接受最长正确前缀 + 拒绝处自己采样 1 个

例: 草稿猜 [天,气,真,好,呀]
    目标验证: 气✓ 真✓ 好✓ 玩✗（草稿第5个"呀"错）
    产出: [气,真,好,玩] —— 一次前向 4 个 token
```

提升接受率 = 让草稿更像目标，这是 4 种草稿范式（第 5 部分）的全部设计目标。

## 2.3 三种适配模式与"继承换芯"惯用法

### 模式一：继承换芯（根目录所有文件）

以 `kimi_k3_mtp.py` 为例（92 行，三种惯用法齐全）：

```python
class AscendKimiK3MultiTokenPredictorLayer(UpstreamKimiK3MultiTokenPredictorLayer):
    def __init__(self, config, vllm_config, prefix):
        # 惯用法①: 不调 super().__init__()，直接调爷爷类 nn.Module 的构造。
        # 上游父类构造硬编码了 AMD 解码层；跳过它就不会构建无用模块。
        # 合法性: nn.Module.__init__(self) 只做内部字典初始化
        #（_parameters/_modules），是后续 self.xxx 赋值的前提。
        nn.Module.__init__(self)

        self.enorm = RMSNorm(...)                    # 硬件无关部分照抄
        self.eh_proj = nn.Linear(2*H, H, bias=False)
        self.mtp_block = AscendKimiDecoderLayer(...) # 惯用法②: 核心替换点

        # 惯用法③: 浅拷贝配置后改字段，不污染共享 config
        block_config = copy.copy(config)
        block_config.attn_res_block_size = None
    # 不重写 forward —— 前向逻辑完整继承父类
```

**上面代码涉及的两个 Python 机制**：

- **MRO（方法解析顺序）**：`class A(B, C)` 多继承时，Python 按 C3 线性化决定方法查找顺序（B → C → object）。`class MiniMaxM3SparseAttention(nn.Module, AttentionLayerBase)` 靠 MRO 同时拥有 nn.Module 的模块管理能力与协议方法；`class DSparkDeepseekV4ForCausalLM(nn.Module, DeepseekV2MixtureOfExperts, SupportsEagle3)` 同理——`Supports*` 接口类一律放继承列表末尾，只做能力声明。`super().__init__()` 也是沿 MRO 找"下一个"父类，而非字面上的父类。
- **`@property` 代理**：把方法伪装成只读属性，用于把深层属性透传到外层。kimi_k3.py 的标准范例：

  ```python
  @property
  def _attention_layer(self):          # 外部写 self._attention_layer 时自动调用本方法
      return self.mla_attn.mla_attn    # 深层对象，外部无需知道包装层级
  @property
  def kv_cache(self):
      return self._attention_layer.kv_cache   # 链式代理
  ```

### 模式三：加载期修补

`load_weights` 里做手术：QuaRot 旋转对齐（5.4）、名称重映射（kimi 的 `fused_bfg_proj`）、scale 重命名（`weight_scale_inv → weight_scale`）。

### 权重加载协议

```
load_weights(weights)  收到 (名字, 张量) 迭代器（流式，可能几百 GB）

stacked_params_mapping = [
    (".qkv_proj", ".q_proj", "q"),   # checkpoint 的 q_proj → 融合参数 qkv_proj 的 "q" 分片
    ...
]
param.weight_loader(param, 权重, shard_id)   # 并行层自带加载器处理 TP 切片
```

`AutoWeightsLoader` 自动匹配普通参数；`packed_modules_mapping` 声明融合关系；专家权重走四元组映射（名字/权重名/专家id/分片id）。MiniMax 的手写加载器统计 loaded/skipped 及原因——**排查权重问题第一入口**。

**load_weights 里的高频语法**（kimi_k3.py / minimax_m3.py 实例）：

- **生成器 `yield`**：`def remap_mixed_gate_weights(): for args in weights: ... yield args`——`super().load_weights(remap_mixed_gate_weights())` 传入的是生成器对象，权重**逐条惰性产出**，不物化几百 GB 的中间列表。yield 所在函数调用时不执行任何代码，每次被迭代才推进到下一个 yield；
- **`for...else`**：`for source, target in mapping: ... break / else: yield args`——循环**没有被 break 打断**、正常跑完时才执行 else 分支。"全部不匹配才透传"的标准写法，等价于设一个 `matched` 标志位但更简洁；
- **元组解包与切片**：`name, loaded_weight = args[:2]`（流元素可能是二元或三元组，先切前两个）；`kwargs = dict(args[2]) if len(args) > 2 else {}`（条件表达式 + 字典拷贝，防止原地修改污染原数据）；
- **字典推导建索引**：`params_dict = dict(self.named_parameters())`——一次性建好"参数名 → 参数"，后续每条权重 O(1) 查找，避免逐条线性扫描。

## 2.5 公共基础设施精讲

### 2.5.1 `common/ops/sequence_parallel.py`

**`sp_shard(x)`**：

```
x [N=1003, H]，tp=8
   │ (-N) % tp = 5 → F.pad 补零到 1008      （负数取模保证非负）
   ▼
x [1008, H] → 均分 → 每卡 [126, H]
```

对齐原因：集合通信要求各卡形状严格一致。

**`sp_all_gather(x)`**：

```
每卡 [126, H] → all_gather(dim=0) → 每卡 [1008, H]（全量副本，含 5 个假 token）
```

**`sp_reduce_scatter(x)`**：

```
每卡 partial [1008, H]（行并行部分和）
   → reduce_scatter → 每卡 [126, H]（自己那段完整和）
   一次通信同时完成"求和+重切"，比 all_reduce 后再切片通信量减半
```

**`sp_padding_mask`**：标记假 token 行（`forward_context.is_padding`），MoE 内核跳过假行。

NPU 适配：优先走 TP 组 `DeviceCommunicator` 的 `custom_all_gather/custom_reduce_scatter`（昇腾优化 HCCL 通道），失败回退 vLLM 通用接口。

### 2.5.2 `layer/attention/layer.py`（DSAAttention）

DeepSeek-V4 稀疏注意力的元数据载体（计算在 `vllm_ascend/attention/dsa_v1.py`）。两个机制：

1. **压缩比→后端**：`compress_ratio=4` → C4 后端；`128` → C128 长程；其余 → SWA；
2. **`get_kv_cache_spec()` 的把戏**：申报 `block_size = 物理块 × 压缩比`——调度器以 token 记账，cache 实际按压缩状态存，块大小放大 ratio 倍后账自动算平。spec 申报的是**语义**而非物理布局。

## 3.1 DeepSeek V4

### 模型卡片

- N 层 `DeepseekV4DecoderLayer`（全 MoE），注意力为 **DSA 稀疏注意力**，残差流为 **Hyper-Connections 多路**；
- 多模态（V4-VL）= 视觉塔 + 语言主干；投机解码 = MTP + DSpark 双草稿。

### 3.1.0 完整前向流转（input_ids → logits）

入口：`deepseek_v4/model.py: DeepseekV4Model.forward` → `AscendDeepseekV4ForCausalLM.compute_logits`

```
第 1 步 词嵌入（PP 首卡；中间卡从 IntermediateTensors 恢复 hidden/residual）
    input_ids [N] ──VocabParallelEmbedding──→ hidden [N, H]
第 2 步 残差流展开（hc_expand）
    hidden [N, H] ──复制 hc_mult 份──→ [N, hc_mult, H]      例: [N, 4, 4096]
    （SP 开启时先 sp_shard → [N/tp, hc_mult, H]，并标记 padding 掩码）
第 3 步 主循环: for layer in layers[start:end]，每层 8 个子步:
  3.1 npu_hc_pre_v2:   残差流 [N, hc_mult, H] → 层输入 [N, H] + 混合系数
  3.2 RMSNorm:         [N, H] → [N, H]
  3.3 DSA 稀疏注意力:   normed [N, H] → q/kv 投影 + compressor + indexer
                       + 稀疏注意力（详见 3.1.2 三组件 shape 流）→ attn_out [N, H]
  3.4 npu_hc_post:     attn_out 混回残差流 → [N, hc_mult, H]
  3.5 npu_hc_pre_v2（FFN 段）
  3.6 npu_rms_norm_cast: 一次归一化同时产出 bf16 输入 [N, H] + FP32 路由输入 [N, H]
  3.7 MoE:             FP32 打分 → top-k → 融合 MoE + 共享专家 → [N, H]（3.1.3）
  3.8 npu_hc_post → 残差流 [N, hc_mult, H]
第 4 步 hc_head 混合折叠: [N, hc_mult, H] → [N, H]
    （投机解码开启时: 折叠前的多路隐状态另存缓冲，
      供 MTP/DSpark 经 get_mtp_target_hidden_states() 取用）
第 5 步 SP 收尾: sp_all_gather → [N_full, H]，裁掉 padding 行
第 6 步 最终 RMSNorm → [N, H]
第 7 步 lm_head（PP 末卡）: [N, H] → logits [N, E]
    decode 时只对最后位置采样: logits[-1] [E]
```

### 3.1.1 整体结构与主干 shape 流

```
input_ids [N]
   │ VocabParallelEmbedding [E, H]
   ▼
hidden [N, H]
   │ hc_expand（复制展开）
   ▼
hidden [N, hc_mult, H]                       例: [N, 4, 4096]
   │ × N 层（每层内部见下）
   ▼
hidden [N, hc_mult, H]
   │ hc_head（混合折叠）
   ▼
hidden [N, H] → RMSNorm → lm_head [H, E] → logits [N, E]
```

**Hyper-Connections**：层前 `hc_pre` 把多路残差混合出本层输入，层后 `hc_post` 把子层输出混回各路。NPU 上是融合算子 `npu_hc_pre_v2/npu_hc_post`。

### 3.1.2 DSA 三组件与 shape 流（本族灵魂）

```
hidden_states [N, H]
   ├───────────────────────────────────────────────┐
   ▼                                               ▼
[Compressor 压缩器]                        [Indexer 索引器]        [主注意力]
                                            （见下）               MLA 精确注意力
                                                                   只算 [滑窗+TopK]
```

**① Compressor——"会议纪要"（每 ratio 个 token 压一份摘要）**

```
hidden_states [N, H]
   │ wkv/wgate 门控投影 + ape 位置表 + RoPE（rotary_mode=2）
   │ torch.ops._C_ascend.compressor（单个融合算子）
   ▼
compressed_kv [N/ratio, coff·d_h]     例: ratio=4, N=512 → [128, coff·128]
   │ slot_mapping → scatter 进压缩 cache
   ▼
压缩 cache（FP32 状态：kv_state + score_state，跨 token 递归更新）

ratio=4:  产出 kv+score 两段（细粒度，供 indexer TopK）
ratio=128: 产出长程粗粒度状态
```

**② Indexer——INT8 闪电索引器（DeepSeek-V3.2 技术）**

```
qr [N, q_lora]                              例: [512, 1536]（复用主注意力的 Q 压缩！）
   │ wq_b 升维
   ▼
q_raw [N, n_heads·128] → 部分 RoPE（只旋尾部）→ Hadamard 旋转
   │ INT8 动态量化
   ▼
q_int8 [N, n_heads, 128]

压缩 key（来自 Compressor）→ Hadamard → INT8 → scatter 进 k_cache/scale_cache

npu_quant_lightning_indexer_v2 融合核（一次完成）:
   q_int8 × k_cache → 打分（含 weights_proj 逐头加权 × softmax_scale）
   → 逐 query TopK
   ▼
topk_indices [N, 1, index_topk]             例: [512, 1, 2048]
```

**Hadamard 旋转为什么减量化误差**：INT8 按最大值定 scale；注意力分数由少数大分量主导时小分量被吃掉。Hadamard（±1 正交阵）把能量摊平到所有维度（"均富"），相对量化误差更均匀。

**双流重叠（NPU 亮点）**：Cube 引擎算 matmul 的同时 Vector 引擎做量化/散射，`npu_stream_switch` + event 编排 Part0-3 四段流水。

> **语法点** `torch.ops._C_ascend.compressor(...)`：`torch.ops` 是算子命名空间对象，**属性访问即触发算子查找**（C++/AscendC 注册的算子打包在 `_C_ascend` 扩展里）；同理 `torch.ops.vllm.minimax_m3_sparse_forward(...)` 是 Python 侧注册的自定义算子。
>
> **语法点** `tensor.numel()`：返回元素总数（所有维乘积），热路径上"空张量快速跳过"的惯用判断：`if slots.numel() == 0: return`（比 `if len(x) == 0` 更普适——多维张量没有 len 语义歧义）。

**③ 主注意力——完整 MLA（在 1.5 基础版之上再加）**

```

   │ wq_a → [N, q_lora] → norm → wq_b → q [N, h_q·(d_nope+d_rope)]
   │ wkv → kv [N, d_lora]；k_rope [N, d_rope]        （cache 只存这两段）

```

### 3.2.2 engram 记忆模块（engram/，7 文件）——三步流程与 shape

**一句话**：按"最近读过的短语"查卡片的外挂记忆库。

```
【第 1 步 滚动哈希】hash_state.py
  输入: input_ids [N]（+历史窗口）
  每层每头一组素数，对多阶 n-gram 做滚动异或多项式哈希:
      hash = (Σ token_id[i]·base^i) mod prime
  输出: hashes [N, num_heads]（桶号，int）
  每头不同素数 = 多路独立检索
  历史三级回退: 当前 chunk → runner 回看窗口 → SWA slot cache
  （图像哨兵 token 排除在 n-gram 外）

【第 2 步 查巨型嵌入表】embedding.py + npu.py
  表: [num_rows, dim] INT8 + 组32缩放（每 32 个值共享 FP8 scale，即 MX 格式）
  gather: hashes [N, num_heads] → 记忆行 [N, num_heads, dim]（INT8）
  反量化 kernel 顺手完成 → [N, num_heads, dim]（BF16/FP32）
  表按 TP×EDP 分片; 放不下时主机 UVA 卸载（aclrtMallocHost
  + HostRegisterV2 设备零拷贝直访，甚至跨进程共享内存）

【第 3 步 投影与门控写回】layer.py + common.py
  记忆行 [N, num_heads, dim]
   │ wkv 投影
   ▼
  key [N, hc_mult, kdim]，value [N, kdim]
   │ 旋转块还原到原始基（QuaRot 逆变换）
   │ 相似度 = RMS 归一化加权内积 → sqrt 量级 → sigmoid
   ▼
  gate [N, ...] ∈ (0,1)
   │ value 门控写回
   ▼
  残差流 [N, hc_mult, H]（对应车道加上门控后的 value）
```

> **语法点** `getattr(obj, "attr", default)` 三参形式：属性不存在时返回默认值而不抛 `AttributeError`——配置探测的标准写法（`getattr(config, "swiglu_beta", 1.0)`）；对应的动态挂属性是 `setattr(obj, "name", value)`（qwen3_dspark 装配私有 embed/lm_head 就用它）。GLM 的 config.py 更进一步**重写了 `__setattr__` / `__getattribute__`**：让顶层配置对象透明镜像文本配置的全部属性（读写双向同步，`_UNMIRRORED_KEYS` 除外）——属性魔法的高级用法。
>
> **语法点** `nn.Module` 的属性陷阱：`self.rot_proj = None` 与 `self.rot_proj = ReplicatedLinear(...)` 的区别——后者经 nn.Module 的 `__setattr__` 被登记进 `_modules`（随 `.to()` 移动、被加载器看见），前者只是普通实例属性。Kimi 投影器的"可选旋转"就靠 None/模块二态实现。

### 3.2.3 mHC 与五类 cache 布局

- mHC：混合矩阵用 **Sinkhorn 迭代**（20 轮）约束到双随机（行和列和≈1，信息守恒）；pre-mix 系数延迟到 `hc_collapse` 才用；算子 `npu_hc_pre_v3/npu_hc_post`。

### 3.3.1 KDA 层完整 shape 流（kda.py）

```
hidden_states [N, H]                          例: [N, 4096]
   │ in_proj_qkvbfg_a（单 GEMM 六投影，输出拼接）
   ▼
[q|k|v|b|f_a|g_a]  [N, 3·(64·128) + b + f_a + g_a]
   │ split
   ├─ q [N, 64, 128] ┐
   ├─ k [N, 64, 128] ├─ 各过 kernel=4 因果卷积（运行时合并为一个卷积:
   └─ v [N, 64, 128] ┘   1D 卷积逐通道独立 → 通道维拼接等价）
   ▼
q/k/v [N, 64, 128]（卷积后的）
   │ 状态更新内核（AscendC）
   │   prefill: run_chunk_kda —— 分块并行（chunk=64）
   │            x [N, 64·128] → reshape [N/64, 64, 64, 128]
   │            gather 初始状态 [B, 64, 128, 128] → 算 → scatter 回缓存
   │   decode:  run_recurrent_kda —— 逐 token 递归，一次最多 8 列
   │            （8 = 最大投机 token 数）
   ▼
o [N, 64, 128]
   │ o_norm（FusedRMSNormGated + sigmoid 输出门，b 参与门控）
   ▼
o [N, 64, 128] → flatten [N, 64·128] → o_proj → [N, H]
```

**状态 shape**：每头一个 `S [d_k, d_v] = [128, 128]`；批处理堆叠为 `[B, 64, 128, 128]` 存在状态 cache（KDA 层的"cache"就是它，没有 KV cache）。

**手算例**（1 头、S 为 2×2、a=0.5、β=0.2）：

```
S₀ = 0
t=1: k₁=[1,0], v₁=[3,1], q₁=[1,0]
   S₁ = 0.2·[[3,1],[0,0]] = [[0.6,0.2],[0,0]]
   o₁ ≈ q₁ᵀS₁ = [0.6, 0.2]
t=2: k₂=[0,1], v₂=[2,2], q₂=[0,1]
   S₂ = 0.5·S₁ + 0.2·[[0,0],[2,2]] = [[0.3,0.1],[0.4,0.4]]
   o₂ ≈ q₂ᵀS₂ = [0.4, 0.4]
```

**有界 sigmoid 遗忘门（GLM safe gate）**：原版 `a = exp(-softplus(x))` 无界不稳；GLM 改 `a = -5 + 6·sigmoid(x) ∈ (-5, 1)` 下界兜底。

**投机解码状态回滚**：草稿 token 可能被拒但状态已被污染——`num_accepted_tokens` 告诉内核只保留前 X 列的状态更新。

> **语法点** `nn.Parameter(torch.empty(...), requires_grad=False)`：推理-only 权重的标准声明。用 Parameter 而非普通 Tensor 的原因：随模型 `.to(device)` 移动、被 `named_parameters()` 枚举、能挂 `weight_loader`；`requires_grad=False` 省掉梯度簿记开销（msa_m3.py 的码本、dflash2 的 base_kernel 都是这样）。`torch.empty` 只分配不初始化——马上会被 checkpoint 覆写，比 zeros 省一次写。
>
> **语法点** `from functools import lru_cache` + `@lru_cache`：按参数缓存函数返回值——GLM 视觉塔的 2D RoPE cos/sin 表对相同 (尺寸, dtype) 只算一次，函数第二次被调用直接返回缓存。
>
> **语法点** 六投影融合的 TP 细节：`f_a/g_a` 跨 TP 复制——复制份的**宽度预乘 tp_size**，加载时强制各 rank 取第 0 份（shard_id=None 表示复制式分片）。这是"参数物理布局与逻辑切分解耦"的典型处理。

        PP 中间卡: 把上一段传来的 residual 填进前几块
第 4 步 主循环，每层（AscendKimiDecoderLayer.forward_attn_residual）:
  4.1 注意力前残差混合: prefix_sum [N_local, H] + 历史块
        → 学习式 softmax 混合 → [N_local, H]（详见 3.4.1）
  4.2 块首层（layer_idx % block_size == 0）:
        block_residual[:, write_idx, :] = prefix_sum; prefix_sum = None
        （写入快照后前缀和清零重启，避免同一信息被重复计入混合）
  4.3 input_layernorm → [N_local, H]
  4.4 SP: sp_all_gather → [N, H]（裁掉 padding 行）
        注意力: KDA 层（AscendKimiK3DeltaAttention）
               或 nope-MLA 层（AscendKimiMLAAttention, use_rope=False）
        SP: sp_reduce_scatter → [N_local, H]
  4.5 prefix_sum += attn_out（块首层从零起算，否则延续之前的和）
  4.6 MLP 前残差混合（mlp_res_*；可见块数 = 历史块 + 本层新写入的块）
  4.7 post_attention_layernorm → MoE 或 dense MLP → [N_local, H]
  4.8 hidden = prefix_sum + mlp_out
  （DSpark aux 捕获: 在指定层把"混合后的流"或"原始前缀和"收进 aux_hidden_states）
第 5 步 末卡: 输出端残差混合（output_attn_res_*，全部块 + 前缀和参与）
第 6 步 SP 收尾 gather（aux 与主 hidden 拼最后一维一次 gather 再 split）
第 7 步 最终 norm → lm_head → logits [N, E]
```

### 3.4.1 注意力残差块（Kimi 独有）shape 流

```
prefix_sum [N, H]                        ← 当前层输入（前缀和流）
block_residual [N, num_blocks, H]        ← 历史快照缓冲（每 block_size 层存一份）

步骤1 拼候选:
  values = cat(block_residual[:, :num_valid, :], prefix_sum.unsqueeze(1), dim=1)
         [N, num_valid+1, H]

步骤2 归一化+打分:
  values_fp32 [N, num_valid+1, H]
  normalized = values / RMS(values)      → [N, num_valid+1, H]
  score_weight = γ [H] ⊙ w [H]           （w 是 res_proj 的可学习权重）
  scores = Σ_d(normalized·score_weight)  → [N, num_valid+1]

步骤3 softmax 混合:
  probs = softmax(scores, -1).unsqueeze(1)   → [N, 1, num_valid+1]
  out = probs @ values_fp32                 → [N, 1, H]
      → squeeze(1)                          → [N, H]
```

> **语法点** `softmax(x, -1)`：`dim=-1` 沿最后一维归一化（每个 token 对自己的候选块独立做 softmax）。
>
> **语法点** `unsqueeze(1)` / `squeeze(1)`：在指定位置插入/移除长度 1 的维，**不改变数据只改形状**。这里 `probs [N, K] → unsqueeze(1) → [N, 1, K]`，目的是让 `probs @ values [N, K, H]` 的 batch 维对齐（`[N,1,K] @ [N,K,H] → [N,1,H]`），算完再 squeeze 回 `[N, H]`。这两个操作是 shape 工程中使用频率最高的工具。

**手算例**（2 候选 2 维，γ=1，w=[0.3,0.2]）：

```
块1 [3,4]: RMS=3.54 → [0.85,1.13] → score₁=0.85×0.3+1.13×0.2=0.48
前缀 [1,1]: RMS=1 → [1,1] → score₂=0.50
softmax → p₁≈0.495, p₂≈0.505
out ≈ 0.495×[3,4] + 0.505×[1,1] = [1.99, 2.48]
```

块首层（`layer_idx % block_size == 0`）把前缀和写入 `block_residual[:, block_write_idx, :]` 后前缀清零重启（避免重复计入）。NPU 有 Triton 融合核 `apply_attn_res` 一次完成全流程。

### 3.4.2 潜空间 MoE shape 流

```
hidden [N, H]                                  例: [N, 4096]
   │ routed_expert_down_proj（H → moe_hidden）
   ▼
x_latent [N, moe_hidden]                       例: [N, 1024]
   │ 融合 MoE（专家全部工作在潜空间: hidden_size=moe_hidden）
   ▼
y_latent [N, moe_hidden]
   │ 可选 routed_expert_norm（RMSNorm）
   │ routed_expert_up_proj（moe_hidden → H）
   ▼
out [N, H] + shared_experts 输出               专家权重总量 ÷ 压缩比
```

down/up 投影挂在 FusedMoE 的 `routed_input_transform/routed_output_transform` 钩子上，随融合内核一起执行。

### 3.4.3 其他要点

- **注意力选择**：`config.is_kda_layer(idx)` 逐层选 KDA 或 **nope-MLA**（`use_rope=False`，位置信息由 KDA 层与残差结构提供）；
- **fused_bfg_proj**：KDA 六投影中的 b/f_a/g 融合；坑：部分 checkpoint 的 f_a 叫 f_b_proj 且跨 TP 复制（shard_id=None = 复制式分片，各 rank 装同一份）；load_weights 生成器 + `for...else` 流式重映射；
- **SP**：无 PP && EP 开 && TP>1 时启用（vLLM 通用 MoE SP 要求 DP>1，K3 在 TP/EP、DP=1 下自管 rank-local 布局）；
- **aux 隐状态两模式**：`dspark_aux_capture_materialized`——物化（逐层收集混合后的流）/ 原始前缀和（默认，供 MLA DSpark）。

### 3.5.1 MSA 块稀疏注意力完整 shape 走查

设序列 1000 token，`sparse_block_size=128` → 8 个历史 block；`topk_blocks=4`。

```
【输入准备】minimax_m3.py:MiniMaxM3SparseAttention._sparse_prepare
hidden [N, H]
   │ qkv_proj（五段融合 [q|k|v|index_q|index_k] 或分离投影）
   ▼
qkv [N, h_q·d_h + 2·h_kv·d_h] + index_q [N, h_kv·idx_dim] + index_k [N, idx_dim]
   │ split + Q/K GemmaRMSNorm（view [N·heads, d_h] → norm → 还原）
   │ 融合路径（非 A5 且 bf16）: torch.ops.vllm.qkv_rmsnorm_rope 一次完成
   │ partial RoPE（只旋前 rotary_dim 维）
   ▼
q [N, 64, 128]  k [N, 8, 128]  v [N, 8, 128]
index_q [N, 8, 128]  index_k [N, 128]     （idx 头数 = KV 头数）

【写 cache】_insert_kv
k/v [N, 8, 128] → clamp(±448)+cast（FP8 固定 scale）→ reshape_and_cache
   → k_cache [2, num_blocks, 128, 8, 128] / v_cache 同
index_k [N, 128] → _scatter_index_cache
   → index_cache [num_blocks, 128, 128]   ← 单头 3D，远小于主 KV！

【索引器选块】AscendMiniMaxM3Indexer
index_q [N, 8, 128] × index_cache 打分（block 级聚合）
   → 每 block 一个分数 → 强制保留初始块/局部块 + top-k
   ▼
topk_idx [h_kv, total_q, topk]              例: [8, N, 4+init+local]

【稀疏注意力】AscendMiniMaxM3SparseImpl
prefill: minimax_m3_sparse_attn（变长批量核: cu_seqlens_q/k + 块统计）
decode:  minimax_m3_sparse_attn_decode（gather topk 块的 KV 精确算）
   ▼
attn_out [N, 64, 128] → flatten → o_proj → [N, H]
```

**块粒度 vs DeepSeek token 粒度**：块粒度打分便宜（8 个分数 vs 1000 个）、索引 cache 更小，但选择更粗（选 1 块 = 128 token 全要）。

### 3.5.2 五段融合投影与量化一致性

```
AscendMiniMaxM3QKVParallelLinearWithIndexer:
输出 5 段 [q | k | v | index_q | index_k]，TP 细节:
  q/k/v: 标准头切分

### 3.5.3 三条算子路径

| 阶段 | AscendC（CANN 原生） | Triton 通用版 | Triton A5 版 |
|---|---|---|---|
| prefill 打分 | ✅ 融合打分+选块 | 分离（score→topk） | 分离 |
| decode 打分 | ✅ 非 A5 | ✅ 含 TP 分片 | ✅ 小核组合 |
| 稀疏注意力 | ✅（K2Q CSR/split-KV） | ✅ | ✅（K/V 拼接布局） |

**A5 版优化**：打分+选块拆成小核接力（编译快、启动延迟低）；保底掩码独立成预计算核；grid 按 AI Core 数自适应 + autotune 剪枝。

**TP 分块并行 decode 打分**（msa_m3.py:_decode_topk_tp_sharded）：

```
每卡 index_q [N_q, h_local, 128] → all_gather(dim=1) → [N_q, h_total, 128]
block 维切: max_block_count=8 块 → 每卡 1 块（示意）
  local_block_table [B, 1]（block_table [B, 8] 的切片）

本地区间打分 → local_topk [h, N_q, k], local_scores [h, N_q, k]
all_gather(dim=-1) → gathered [h, N_q, k·tp]
每头切自己段 → 全局 topk → gather 出对应块 id
← 通信量 = top-k 个数，而非全部块分数
```

### 3.5.4 其他要点

- SwiGLU-OAI：`clamp(gate)·sigmoid(α·gate)·(clamp(up)+β)`；A5+MXFP8 时激活内联动态量化；
- EAGLE3 aux 层默认 `(2, N/2, N-3)`；
- load_weights 五阶段：前缀清理跳过（mtp/rotary/spec）→ scale 重命名 → index_* 特殊权重 → 堆叠映射 → 专家映射 → 兜底，全程统计跳过原因。

**MiniMax M3 文件里的语法集合**（这个模型族把本仓库的语法惯用法用了个遍）：

- **`@dataclass`**：自动生成 `__init__`/`__repr__`/`__eq__`，用于纯数据容器（`AscendMiniMaxM3SparsePrefillMetadata` 等元数据类）；字段以 `名字: 类型` 声明，可带默认值；加 `frozen=True` 则实例不可变（deepseek_v41/glm5next 的拓扑描述类）；
- **`ClassVar`**：`supported_dtypes: ClassVar[list[torch.dtype]]` 标记"类级常量"（所有实例共享，不是实例属性）——与 dataclass 连用时防止该字段被当成实例字段生成 `__init__` 参数；
- **`@staticmethod`**：`ebias_weight_loader(param, weight)` 不接收 self（纯工具方法），通过类名或实例直接调用；对应地 `@classmethod` 接收 cls，常用作"替代构造器"；
- **`del num_kv_heads, cache_dtype_str`**：显式删除未使用的参数名——函数签名由协议规定必须接收、但本实现用不到；del 向读者与 linter 声明"有意忽略"（比 `# noqa` 更明确）；
- **`dict.fromkeys(candidates)`**：由列表建字典（值全为 None）再迭代其 keys——比 `list(set(...))` 好在**保序去重**（msa_m3.py 的前缀候选探测）；
- **位运算技巧**（qwen3_dflash2.py 分组卷积）：`block_size & (block_size - 1) == 0` 判断 2 的幂；是 2 的幂时 `x & (block_size - 1)` 等价于 `x % block_size` 且位运算更快；
- **f-string 调试语法 `f"{x=}"`**：输出 `x=<值>`（变量名和值一起打），assert 消息标配：`f"but get {linear_weight.shape[1]=} and {rotation_weight.shape[0]=}"`——比手写 `f"... {linear_weight.shape[1]} ..."` 多打印了表达式本身；
- **`enumerate(islice(self.layers, start, end), start=start_layer)`**：`islice` 只迭代区间内的层（跳过 PP 上归属其他卡的层，且不需要切片拷贝）；`enumerate` 的 `start` 参数让计数器与全局层号对齐——循环体内 `layer_idx` 直接可跟配置里的层号比较；
- **闭包 + `nonlocal`**：`def mark_loaded(...): nonlocal loaded_tensors; loaded_tensors += 1`——内层函数要**修改**外层函数的变量必须声明 nonlocal，否则 Python 会把它当成新的局部变量（读取则不需要）。

# 第 4 部分：注意力后端三件套协议

一个推理 step 的完整时序（以 MiniMax M3 为教材）：

```
【构建期】（每层一次）
MiniMaxM3SparseAttention.__init__
  ├─ static_forward_context[layer_name] = self        挂号
  ├─ self.impl = AscendMiniMaxM3SparseImpl(...)       计算实现
  └─ self.indexer / self.kv_cache = torch.tensor([])  运行时由分配器填充

【每一步】
① 调度器产出 CommonAttentionMetadata:
     query_start_loc [B+1]      （各请求 query 累计偏移，CPU+设备双份）
     seq_lens [B]               （各请求 KV 长度）
     block_table [B, max_blocks]
     slot_mapping [N]

② MetadataBuilder.build(common):
     split_decodes_and_prefills 按 query 长度分组
     prefill 子元数据:
       cu_seqlens_q [B_p+1] = (query_start_loc[切片] - num_decode_tokens).int32
       context_lens [B_p]    = seq_lens[切片] - query_lens   （预分配缓冲异步填充）
       block_table 切片 [B_p, max_blocks]
     decode 子元数据:
       decode_query_len（投机解码时 >1）
       seq_lens/block_table 切片 [B_d, ...]

③ 模型 forward 逐层:
     minimax_m3_sparse_forward(q, k, v, index_q, index_k, attn_out, layer_name)
       → 按名找回层实例 → _run_sparse_attention:
            _insert_kv(k [N,8,128], v [N,8,128], index_k [N,128])
            topk = indexer(index_q [N,8,128]) → [h_kv, N, topk]
            impl.forward(层, q [N,64,128], kv_cache, topk, out [N,64,128])

④ 图重放: 参数由 builder 的预分配缓冲承载（地址稳定，ACL Graph 兼容）
```

**预分配缓冲的原因**：ACL Graph 记录的是张量**地址**；每步重建张量地址会变、图失效。预分配一次、每步 `copy_` 原地更新。

# 第 5 部分：投机解码草稿模型族

## 5.1 MTP（Multi-Token Prediction，串联单步草稿）

```
【输入】目标隐状态 h_prev [N, H]（V4 是多路 [N, hc_mult·H]）
        当前 token embedding e [N, H]

enorm(e) [N, H] ─┐
                 ├→ cat [N, 2H] → eh_proj → [N, H]
hnorm(h) [N, H] ─┘
   │ mtp_block（复用目标解码层结构）
   ▼
hidden [N, H] → shared_head/lm_head → draft_logits [N, E]

多步: spec_step_idx % num_mtp_layers 轮转选层
```

实现：deepseek_v4/mtp.py、glm5next/mtp.py（`fused_eh_norm` Triton 单内核完成置零+双 norm+拼接；贪心草稿用 vocab 并行 argmax 免物化全词表 logits）、kimi_k3_mtp.py、deepseek_mtp.py。

## 5.2 DSpark（块级草稿）

```
【上下文预写入】（省去草稿块对上下文的重复前向）
目标 aux 隐状态 h_aux [N, num_target_layers·H]
   │ main_proj（列并行）→ [N, H] → context_norm
   ▼
context [N, H]
   │ 各草稿层: fused_qkv_a_proj → 取 [q_lora:] 段
   ▼
kv_no_split [N, d_lora] → RoPE → exec_kv_prefill → scatter 进草稿 SWA cache

【草稿块前向】
draft_embeds [N_blk, H] → 草稿层×n → hidden [N_blk, H]
   → lm_head → logits [N_blk, E]
   → + Markov 头偏置（低秩 bigram: 上一草稿 token → logits 偏置 [E]）
   → confidence 头 → sigmoid → 接受概率 [N_blk]
```

实现：deepseek_v4/dspark.py、deepseek_v41/dspark.py（3 草稿块）、kimi_k3_dspark.py（MLA 版，支持**双向注意力**——草稿块内 token 互相可见不算作弊，"未来"正是要猜的对象）、qwen3_dspark.py。

## 5.3 EAGLE3（多层特征直接融合）

```
目标 3 层 aux 隐状态: h₁,h₂,h₃ 各 [N, target_H]
   │ cat
   ▼
[N, 3·target_H] → fc → [N, H] → 草稿层 → logits [N, E]
目标侧: set_aux_hidden_state_layers((2, N//2, N-3)) 声明捕获层
```

**EAGLE3-VWN 草稿一步的完整流转**（llama_eagle3_vwn.py，从目标隐状态到草稿 logits）：

```
第 1 步 combine_hidden_states: 目标 3 层隐状态 h₁,h₂,h₃ [N, target_H]
        → cat [N, 3·target_H] →（可选 input_norm）→ fc → 条件向量 [N, H]
第 2 步 词嵌入: 草稿上一步 token [N] → embed_tokens → embeds [N, H]
第 3 步 进入 VWN 解码层（仅 layer_idx==0 真正计算，其余层直通）:
  3.1 PreVwnLayerV1 入口:
      norm(e) ⊕ norm(h) → cat [N, 2H] → fc → x [N, H]
      → x.view(-1, H/m) [N·m, H/m] → upward → [N·m, wd/m]
      → view(-1, wd) → wider [N, wd]                （wd = H·r）
  3.2 downward_and_forgot（一次投影出两段）:
      wider.view(-1, wd/m) [N·m, wd/m] → 线性 → view [N, H+wd]
      → split([H, wd], dim=-1) → hidden [N, H] + 宽流残差 res [N, wd]
  3.3 pre_attention_layernorm → self_attn（标准 GQA + RoPE）→ [N, H]
  3.4 upward_after_attn: [N, H] → 分组升维 → wider [N, wd] + res
  3.5 downward_and_forgot_after_attn → split → hidden + res
  3.6 post_attention_layernorm → mlp → upward_after_mlp → + res → [N, wd]
  3.7 downward: [N, wd] → 分组降维 → hidden_states [N, H]
第 4 步 norm(hidden, residual) → 最终隐状态 [N, H]
        （同时返回未 norm 的 hidden —— EAGLE3 协议供特征级验证）
第 5 步 lm_head（草稿词表）→ logits [N, draft_vocab]
第 6 步 compute_logits: 按 draft_id_to_target_id [draft_vocab] 映射散射
        → logits_new [N, E]（未映射位填 -inf，softmax 后概率为 0）
```

> **语法点** `x.view(-1, H // m)`：`-1` 表示"该维自动推算"（总元素数 ÷ 其余维乘积）；`out.split([H, wd], dim=-1)` 按给定长度列表切最后一维，返回视图元组，可 `hidden, res = out.split(...)` 一行解包。两者组合实现"分组共享权重的块对角 GEMM"——同一个 (H/m → wd/m) 投影并行处理 m 个分组。
>
> **语法点** `self.register_buffer("mask_hidden", torch.zeros(...), persistent=False)`：buffer 是"随模型移动但不是参数"的张量（`.to(device)` 会带上它）；`persistent=False` 表示不写入 state_dict——避免 checkpoint 保存/加载时出现多余的键。

## 5.4 QuaRot 旋转对齐专题

**问题**：目标做过旋转量化（`h' = Q·h`），草稿要与目标共享隐状态/词表，两侧必须同基。

```
【加载时反旋转】
草稿 fc 层（消费 3 层拼接隐状态）:
   W [H·3, H] @ block_diag(Q, Q, Q) [3H, 3H] → W_aligned [H·3, H]
   （block_diag 一次 GEMM 转三段，省 3 倍矩阵物化）
草稿 embed_tokens:
   E [E, H] @ Qᵀ → E_aligned [E, H]
草稿不拥有 embed/lm_head: 从目标 checkpoint 取权重对齐后装配独立副本
   （原则: 不修改共享权重）

【分片定位工程】_find_safetensors_weight
   优先查 *.safetensors.index.json 的 weight_map（O(1) 定位张量所在分片）
   safe_open().get_slice()[start:end] 惰性切片只读需要的行
   词表并行: shard_indices.org_vocab_start/end_index 标记本 rank 行区间
   对齐后: layer.weight[:loaded_rows].copy_(aligned); [loaded_rows:].zero_()
```

> **语法点** `if shard_name := weight_map.get(weight_name):`——**海象运算符 `:=`**：在条件表达式内赋值并立即使用，等价于"先赋值、再判断"，省掉两行；只在海象形式下合法出现在 if/while 条件里。
>
> **语法点** `with safe_open(shard, framework="pt") as f:`——**上下文管理器**（对象实现 `__enter__`/`__exit__`）：进入 with 块时执行 `__enter__` 返回句柄，离开时（即使抛异常）自动执行 `__exit__` 释放文件资源。`f.get_slice(name)[a:b]` 是惰性切片视图，只把需要的行读进内存——大词表只取本 rank 的行区间。
>
> **语法点** `layer.weight[:loaded_rows].copy_(aligned)`：`copy_` 带下划线 = **原地操作**（in-place，PyTorch 惯例：所有 `_` 后缀方法改自身不新建张量）；切片 `[:loaded_rows]` 在赋值左侧是"写视图"——只覆盖前若干行。

## 5.5 DFlash2（候选格草稿）

```
【动态分组卷积】（注意力/MLP 前后各包一层，核随输入自适应）
hidden [N, H]
   │ unflatten(-1, (G, gs))          → blocks [N, G, gs]     例: [N, 32, 128]
   │ coefficients = base[1,taps,G,gs] + delta[N,1,G,1]        （核 = 静态基 + 输入增量）
   │   delta 来自 kernel_projection: [N, H] → [N, 2·taps·G]
   │ tap-0 逐点乘 + 高阶 tap 右移累加（position ≥ tap 掩码保证块内因果）
   ▼
out [N, G, gs] → flatten(-2) → [N, H]

【候选生成】compute_candidates（共享目标 lm_head 做全词表 TopK）
hidden [N, H] → lm_head → logits [N, E_shard]
   → 剔除 padding 位 → topk → values/ids [N, K]
   → TP>1: all_gather → [N, K·tp] → 全局 topk → [N, K]

【候选格边打分】CandidateSelector
candidate_ids [B, L, K]
hidden [B, L, H] → flatten(0,1) [B·L, H] → proj → [B·L, rank] → view [B, L, rank]
successors = succ_codebook[candidate_ids]      → [B, L, K, rank]
predecessor_ids = cat(anchor[B,1,K], candidate_ids[:,:-1])  → [B, L, K]
predecessors = pred_codebook[predecessor_ids]  → [B, L, K, rank]
edge_scores = unary[:,:,:,None] + einsum("blpr,blcr->blpc",
                predecessors ⊙ hidden[:,:,None], successors)  → [B, L, K, K]
```

**NPU 适配**：`torch._check` 向 Dynamo 传播形状约束（NPU unquantized_gemm fake 只吃 2D → 展平投影再还原）；`set_model_tag("dflash2_candidate_selector")` 隔离编译缓存。

**本节代码的语法点**：

- **`torch.einsum("blpr,blcr->blpc", A, B)` 逐字符解读**：输入 A 的维标 b,l,p,r，B 的 b,l,c,r，输出 b,l,p,c。规则：**r 出现在两个输入但不在输出 → 沿 r 求和（内积）**；b,l 出现在两输入与输出 → 作 batch 维对齐广播。一行表达"批处理双线性型"，等价于 `(A.unsqueeze(-1) * B.unsqueeze(-2)).sum(-1)` 但高效得多；
- **`torch._check(cond)`**：给 torch.compile 编译器看的断言——把形状约束**传播进编译图**（普通 `assert` 编译器看不见，会被优化掉）；
- **`with torch.device(d):` / `with set_model_tag(tag):`**：上下文管理器临时改变全局状态（默认设备/编译标签），离开 with 块自动恢复——避免全局状态泄漏的标准写法；`with torch.device(d): layer = Linear(...)` 创建的层直接分配在 d 上；
- **`F.pad(blocks[:-tap], (0, 0, 0, 0, tap, 0))`**：pad 元组从最后一维往前、每维一对 `(左, 右)`——这里最后两维不补 (0,0)(0,0)、第一维左侧补 tap 个零，实现序列右移 tap 位（因果方向）；
- **`x.unflatten(-1, (G, gs))`**：把最后一维拆成 (G, gs) 两维（`[N, H] → [N, G, gs]`），是 `view` 的语义化包装（不用自己算 H = G×gs）。

## 8.2 调试技巧

1. **权重加载**：看加载统计日志（loaded/skipped by reason）——`missing_param` 查 stacked_mapping，`pp_missing` 正常；
2. **形状对不上**：从报错形状反推——第一维 `N` 是展平 token 流；头维在前（如 `[h_kv, N, topk]`）多为"每头独立"的中间量；
3. **分支是否走到**：`logger.info`（不用 print——多进程刷屏无序）；
4. **NPU 性能**：先查热路径 `.item()`/`.cpu()`（同步！），再对照各模型的"算子路径决策表"确认走了预期融合路径。

## 8.3 FAQ

**Q1：为什么到处 `.contiguous()`？**
切片/转置产生跨步视图，很多 NPU 算子只吃连续内存；`.contiguous()` 物化连续副本。

**Q2：`nn.Module.__init__(self)` 不调 super 直接调爷爷类，安全吗？**
漏掉的正是要跳过的父类逻辑（上游硬编码的 AMD/NVIDIA 组件），是**有意的**；风险是上游父类将来加了必要状态会踩坑，故每个这样写的类都有注释说明。

**Q3：forward 里为什么不判断 batch 维？**
vLLM v1 把 batch 展平成 `[N, H]` token 流；请求边界在元数据（`query_start_loc [B+1]`）里，模型统一按流处理。

**Q4：`static_forward_context` 是什么？**
全局字典 `{层名: 层实例}`。编译图把注意力变成不透明算子节点，运行时按名找回真实 Python 对象——编译世界与运行世界之间的挂号本。

**Q5：GLM 尾部环为什么禁用 prefix caching？**
尾部环是"未凑满一池的原始 K/gate"，请求私有瞬态数据，语义上不该共享；且每请求 ≤1 块，共享无收益。

**Q6：INT8 量化前为什么 Hadamard 旋转？**
旋转把尖峰分布摊平（能量均匀到各维），同样 scale 下相对误差更小。DeepSeek 索引器和 QuaRot 同一原理。

**Q7：`.item()` 慢在哪？**
NPU 异步执行，`.item()` 要值本身 → CPU 停等 NPU 算完 + 拷回。decode 热路径每步一次 = 吞吐腰斩。

**Q8：`get_kv_cache_spec` 返回 None 什么意思？**
该层不需要 KV cache——纯线性注意力（KDA）层用固定状态代替。调度器据此做混合显存核算。

**Q9：`sp_shard` 前为什么补零？**
集合通信要求各卡形状严格一致；补零对齐后均分，假 token 用 padding mask 标记、MoE 跳过、结果裁掉。

**Q10：模型文件从哪读起？**
按 2.4 骨架自下而上（MLP → MoE → Attention → DecoderLayer → Model → ForCausalLM）；先读类 docstring，再钻方法。
